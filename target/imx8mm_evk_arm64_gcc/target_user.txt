○概要

IMX8MM_EVK依存部は，NXP社のi.MX8M Mini EVKのCortex-A53のAArch64モード
をサポートしている．サポートしているプロセッサ数は，1～4個であり，ディ
フォルトでは4個で動作する．

現状サポートしているボードは次の通りである．

●ボード

動作確認を行ったボードは次の通りである．

・NXP MCIMX8MM-EVK

●i.MX BSP

動作確認したi.MX BSPのバージョンは次の通りである．

  - i.MX Linux 4.14.98 BSP

●コンパイラ

動作確認を行ったGCCは，ARMから提供されている

   gcc version 11.2.1 20220111 
   https://developer.arm.com/tools-and-software/open-source-software/developer-tools/gnu-toolchain/gnu-a/downloads

である．

●デバッグ環境

デバッグ環境としては，京都マイクロコンピュータ製のPartner-Jet2 による
デバッグの動作確認を行った．

●実行環境

Partner-Jet2を使用する場合は，本カーネルはPLLやDDR等の初期化はu-bootで
実施することを前提としている．

○プロセッサ数

ディフォルトでは，4プロセッサをサポートしている．TNUM_PRCID マクロを
Makefileで設定することにより1～4の範囲で設定することが可能である．


○カーネルのコンフィギュレーション

●カーネルロック方式

ジャイアントロック方式とプロセッサロック方式と細粒度ロック方式をサポー
ト．

●カーネルタイマ方式

グローバルタイマ方式とローカルタイマ方式の両方をサポート．

●スピンロック方式

ネイティブ方式とエミュレーション方式の両方をサポート．ネイティブ方式の
場合の最大数は256個である．


○カーネルの使用リソース

プロセッサ毎にカーネルは以下のリソースを使用する．

・タイマ
  コア内蔵の Secure Physical Timerを使用する．

・UART
  i.MX8内蔵UART4,UART2,UART3を使用可能である.

・プロセッサ間割込み
  0番と1番のプロセッサ間割込みを使用する．

・メモリ
  DDRを使用．
  TEXT      : 0x40000000
  DATA      : 0x40800000

○システムログ機能

システムログ機能は，グローバル方式のみが有効である．そのため，Makefile
の ENABLE_G_SYSLOG を true に定義すること．
システムログ機能では,SIO Port0を使用している.


○ブートの流れについて

i.MX8 BSPではATFを採用しているため，ATFのブートシーケンスに従ってブー
トされる．ATFからNon-SecureのBL33として起動し，PSCIを使用してサブコア
を起動している．


○実行方法

ドキュメント中のパスの記述について：
 <IMX-BSP>   1.1章でi.MX8MMのBSPをセットアップした,imx-yocto-bspフォルダ
 <FMP3>      FMP3カーネルのパッケージを展開したディレクトリ
 <ATF>       ダウンロードしたATFのディレクトリ


1. 準備

(1) 次のように接続する．

USB TypeC  PORT2 : ACアダプタ
USB MicroB DEBUG : ホストPC(U-Boot，Linux ログ出力用)
MicroSDスロット  : 起動用MicroSD
SW1101/1102      : DIPを設定してMicroSDからのブートモードに設定する
                   設定値はボード上のシルクを参照のこと．

(2) ホストPCでターミナルソフトを起動する．
   USBシリアルが2ポートあるため全て接続

1.1. i.MX8MMのBSPのセットアップ

1.1.1. repoユーティリティのインストール，設定

次のコマンドを実行．

$ sudo apt-get install phablet-tools
$ mkdir ~/bin
$ curl http://commondatastorage.googleapis.com/git-repo-downloads/repo > ~/bin/repo
$ chmod a+x ~/bin/repo
$ export PATH=~/bin:$PATH

1.1.2. Yoctoのセットアップ

次のコマンドを実行して，名前とe-mailアドレスを設定．

$ git config --global user.name "Your Name"
$ git config --global user.email "Your Email"

次のコマンドを実行．

$ mkdir imx-yocto-bsp
$ cd imx-yocto-bsp
$ repo init -u https://source.codeaurora.org/external/imx/imx-manifest -b imx-linux-sumo -m imx-4.14.98-2.0.0_ga.xml
$ repo sync

1.1.3. Yoctoのビルド

次のコマンドを実行して，ビルド設定を行う．

$ DISTRO=fsl-imx-wayland MACHINE=imx8mmevk source fsl-setup-release.sh -b imx-4.14.98

次のコマンドを実行して，ソースコードの取得，ビルドを行う．

$ bitbake core-image-minimal

1.2. 起動用SDカード作成

 4GB以上のSDカードを次の手順で，起動用SDカードにする．

(1) i.MX8MM BSPをインストールしたPCにSDカードを挿入．

(2) i.MX8MM BSPに格納されている次のファイルをbzip2コマンドなどで展開．
  imx-yocto-bsp/imx-4.14.98/tmp/deploy/images/imx8mmevk/core-image-minimal-imx8mmevk.sdcard.bz2

(3) 展開したファイルを次のコマンドでSDカードへ書き込む．

$ sudo dd if=core-image-minimal-imx8mmevk.sdcard of=/dev/sdx bs=1M && sync

※ /dev/sdxは各環境の起動用SDカードを示す識別子に読み替える．
  また，パーティション番号を含まないデバイス名を指定する必要がある．
  (OK：/dev/sdc，NG：/dev/sdc1)


2. FMP3のビルド

サンプルアプリを例に説明する．

(1) ビルド実行

$ cd fmp_3.0
$ mkdir OBJ
$ cd OBJ
$ ruby ../configure.rb -T imx8mm_evk_arm64_gcc -w -S 'syslog.o banner.o serial.o logtask.o imx8uart.o chip_serial.o'
$ make clean
$ make fmp.bin

カレントディレクトリのfmp.binが実行バイナリである．


3. ATFのビルド

FMP3のコンソールにUART4(デフォルト)を使用する場合，ATFでCortex-A53(EL3
動作時以外)からUART4をアクセスできないように設定されている.このため
,UART4使用時はATFを変更する必要がある.本章では,UART4をCortex-A53から使
用可能にした,ATFのビルド方法を説明する.
を示す識別子に読み替える．
  また，パーティション番号を含まないデバイス名を指定する必要がある．
  (OK：/dev/sdc，NG：/dev/sdc1)

(1) ATFソースコードのダウンロード

$ git clone -b rel_imx_4.14.98_2.0.0_ga https://github.com/nxp-imx/imx-atf.git

(2) 次のコマンドで, パッチとファイル追加を行う.

$ cd <ATF>
$ patch -p1 < <FMP3>/target/imx8mm_evk_arm64_gcc/imx-atf_ca53-uart4.patch

(3) 次のコマンドで, パッチを当てたATFをビルドする.

$ export ARCH=arm64
$ export CROSS_COMPILE=<IMX-BSP>/imx-4.14.98/tmp/work/imx8mmevk-poky-linux/imx-atf/2.0+gitAUTOINC+1cb68fa0a0-r0/recipe-sysroot-native/usr/bin/aarch64-poky-linux/aarch64-poky-linux-
$ make PLAT=imx8mm clean
$ make PLAT=imx8mm SPD=opteed bl31 CTX_INCLUDE_FPREGS=1

4. 起動用SDカードへの書き込み

i.MX8MM-EVKは，起動用SDカードからロードしてシステムを起動する．起動用
SDカードへのソフトの書き込み方法を説明する．

(1) 以下のコマンドでimx-mkimageを入手する．

$ git clone -b rel_imx_4.14.98_2.0.0_ga https://source.codeaurora.org/external/imx/imx-mkimage
$ git clone https://github.com/Freescale/imx-mkimage.git

(2) ブートイメージ(flash.bin)作成に必要なバイナリを，Linux BSPディレクトリからコピーする.

$ cd imx-mkimage/iMX8M
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/mkimage_uboot .
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/lpddr4_pmu_train_1d_imem.bin .
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/lpddr4_pmu_train_1d_dmem.bin .
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/lpddr4_pmu_train_2d_imem.bin .
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/lpddr4_pmu_train_2d_dmem.bin .
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/u-boot-imx8mmevk.bin-sd u-boot.bin
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/u-boot-nodtb.bin-imx8mmevk-sd u-boot-nodtb.bin
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/u-boot-spl.bin-imx8mmevk-sd u-boot-spl.bin
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/fsl-imx8mm-evk.dtb .
$ cp <FMP3>/OBJ/fmp.bin tee.bin

FMP3でUART4を使用する場合,次のファイルをコピーする.
$ cp <ATF>/build/imx8mm/release/bl31.bin .

それ以外の場合,次のファイルをコピーする.
$ cp <IMX-BSP>/imx-4.14.98/tmp/deploy/images/imx8mmevk/imx-boot-tools/bl31-imx8mm.bin-optee bl31.bin

(3) imx-mkimageでブートイメージを作成する．

$ cd imx-mkimage/iMX8M
$ export ARCH=
$ export CROSS_COMPILE=
$ make -f soc.mak clean
$ make -f soc.mak flash_evk SOC=iMX8MM

(4) Linux PCに起動用SDカードを挿入し，flash.binを書き込む．

sudo dd if=flash.bin of=/dev/sdx bs=1K seek=33 status=progress conv=fsync

※ /dev/sdxは各環境の起動用SDカードを示す識別子に読み替えてる．
  また，パーティション番号を含まないデバイス名を指定する必要がある．
  (OK：/dev/sdc，NG：/dev/sdc1)


5. 起動方法

i.MX8MM-EVKに起動用SDカードを挿入し，電源を入れると起動する．


6. ICEによるデバッグ方法

(1)事前準備
PARTNER-Jet2の設定を変更し，起動からデバッガ接続までの待ち時間を短縮す
る.具体的には以下の手順を実行する．

  (1) PARTNER-Jet2のi.MX8M mini用プロジェクトディレクトリを開きます.
      (例)
      C:\Users\Public\Documents\WJET2ARM64\Projects\NXP_Cortex-A53_Cortex-M4_imx8mm_MCX
  (2) NXP_imx8mm_Cortex-A53_MC\core0\JETARM.CFGファイルをテキストエディタで開きます.
  (3) 以下のJTAG ブートwait時間を変更します.
      具体的には2から0.5へと変更します.
-----------------------------------------------------------
; JTAG　ブートwait時間
; デバッガ起動時および初期化時に，リセット出力後デバッグモードに
; 入るまでの待ち時間を秒単位で指定します.
; 通常は，この設定は必要ありません.(デフォルトは 0設定)
; CPUのリセット解除後にユーザプログラムを指定間走らせることで必要な初期化を行い，
; その後デバッガを接続する設定です.
; 第２パラメータに BYPASS を設定すると，指定された待ち時間の期間にJTAGの接続テスト(BYPASSコマンド)を
; 行い，接続テストにパスした時点でウェイトを抜け起動動作を再開します.FPGAのコンフィギュレーション待ちなどで待ち時間が変化する場合に
; 最適な待ち時間を挿入できる場合があります.
; EX.	J_BOOT_WAIT	2	... 2秒の待ち時間
; EX.	J_BOOT_WAIT	0.5	... 0.5秒の待ち時間
; EX.	J_BOOT_WAIT	10,BYPASS ... 最大10秒の待ち時間/BYPASSテストにパスした時点でウェイトを抜けます.
;J_BOOT_WAIT	0
J_BOOT_WAIT	0.5
;J_BOOT_WAIT	2
-----------------------------------------------------------

(2) 起動用SDカードをi.MX8M Mini開発ボードに挿入する．
(3) PARTNER-Jet2を電源ONする．
(4) i.MX8M Mini開発ボードを電源ONする．
(5) PARTNER Debugger(ARM64)を起動する．
(6) U-Boot起動途中で停止するので，以下のアドレスに
    HWブレークポイントを設定する．
    0xBE00_0000(FMP3エントリポイント)
    コマンド
    BR BE000000,EX
(7) デバッガで「実行」を行うと，0xBE00_0000でブレークする．
(8) デバッグしたいFMP3のELFファイルを選択し，ロードする．
(9) デバッガにて「実行」を行うと，ロードしたFMP3が実行される．
